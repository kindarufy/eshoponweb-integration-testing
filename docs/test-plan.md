# Тест-план интеграционного тестирования eShopOnWeb

## 1. Цель тестирования

Проверить работу eShopOnWeb как единой системы после интеграции основных модулей: каталога, корзины, авторизации, оформления заказа, истории заказов и административной части.

## 2. Объект тестирования

Microsoft eShopOnWeb — ASP.NET Core reference application.

Основные зоны:

- Web UI;
- Catalog;
- Basket;
- Checkout;
- Identity/Auth;
- Orders;
- Admin UI;
- PublicApi;
- Database/seed data.

## 3. Вне области тестирования

В рамках этого учебного кейса не выполняется:

- нагрузочное тестирование;
- полноценное security-аудирование;
- проверка платёжных интеграций;
- проверка production deployment в Azure;
- анализ покрытия unit-тестами оригинального проекта;
- изменение исходного кода eShopOnWeb.

## 4. Типы тестирования

- Smoke testing;
- Big Bang Integration Testing;
- Manual E2E testing;
- базовая проверка авторизации;
- базовая проверка пользовательского ввода;
- проверка тестового окружения.

## 6. Критерии успешности

Тестирование считается успешным, если:

- ключевые страницы открываются без 5xx-ошибок;
- каталог отображает seed-товары;
- корзина сохраняет добавленные товары в рамках пользовательского сценария;
- авторизация через demo-user работает;
- оформление заказа завершается ожидаемым результатом;
- admin-сценарии проверены с учётом зависимости от PublicApi;
- ошибки не раскрывают лишнюю техническую информацию пользователю;
- все findings оформлены с понятными шагами и статусами.

## 7. Риски

| Риск | Влияние | Как снизить |
|---|---|---|
| Разные адреса при Docker и local run | Postman-тесты могут обращаться не туда | Использовать environment variables |
| HTTPS local certificate | Postman может блокировать запросы | Использовать HTTP Docker endpoint или настроить SSL |
| Admin UI зависит от PublicApi | Admin-сценарии могут падать при незапущенном API | Запускать Web + PublicApi |
| Big Bang плохо локализует дефекты | Сложнее понять источник ошибки | Добавить API и component-level checks |
